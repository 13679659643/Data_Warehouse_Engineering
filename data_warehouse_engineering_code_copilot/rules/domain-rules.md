# 业务领域约束

## 1. 通用业务规则

- 所有金额字段类型为 `DECIMAL(18,4)`，存储**元**为单位（除非业务库本身为分，需在 ETL 中除以 100）
- 报表展示金额统一保留两位小数，并标注币种（默认 CNY）
- 百分比指标统一保留 1 位小数 + `%` 后缀（如 `40.5%`）
- 时间维度统一基于自然年（1 月-12 月），如需财年另行定义并加前缀（如 `fy_year`、`fy_month`）
- 同比（YoY）/ 环比（MoM）必须处理零值与空值

### 同比口径
```sql
-- 标准 YoY 口径（含边界判断）
CASE
    WHEN py_amt IS NULL OR py_amt = 0 THEN NULL              -- 同期为空或零，返回 NULL
    WHEN cur_amt IS NULL OR cur_amt = 0 THEN -1.0            -- 本期为零、同期非零，返回 -100%
    ELSE (cur_amt - py_amt) / py_amt
END AS yoy_rate
```

### 环比口径
同 YoY，仅基准换为 `pm_amt`（上月）。

### 排名口径
- 默认 `ROW_NUMBER`（严格唯一），并列场景由业务确认是否切换为 `RANK`/`DENSE_RANK`
- 排序字段不足时用次级字段做 tie-breaker（如 `ORDER BY amt DESC, create_time ASC`）

### 排序键
- 涉及到排序字段（如 metric_sort、dim_sort）的，**起始值从 10 开始，步长 10**，便于后续插入
- 例：10、20、30、40……，新增项可插入 15

### 状态颜色（上层 BI 一致性）
- `__value > 0` → `#1A9018`（草绿色，正向）
- `__value < 0` → `#D64550`（玫瑰红，负向）
- `__value = 0` → `#E1C233`（亮黄，持平）
- 仅对"对比类"指标启用条件色（YoY/MoM/Vs Target），绝对值类不启用

## 2. KPI / 指标定义标准

### 必备属性
每个 KPI 在 `rules/project-context.md` 或独立指标字典中必须明确以下字段：

| 属性 | 说明 |
|------|------|
| 指标编号 | 如 KPI-001，便于跨系统引用 |
| 指标名称 | 业务含义清晰 |
| 业务定义 | 一句话业务口径 |
| 计算公式 | 精确的 SQL / 数学表达式 |
| 数据来源 | 库.表.字段（必须存在） |
| 粒度 | 最细可用粒度（用户/订单/SKU 等） |
| 更新频率 | 实时 / 每日 / 每周 / 每月 |
| 目标值 / 基准 | 红绿灯阈值（如 ≥ 95% 绿，90~95% 黄，< 90% 红） |
| 责任人 | 业务侧 + 数据侧 |
| 适用范围 | 哪些主题 / 报表 |

### 同名指标必须同口径
- 同名指标在不同主题中口径不同 → 必须改名（如 `gmv_gross` vs `gmv_net`）
- 必须在指标字典中显式登记别名与差异

## 3. 数据质量规则

### 五大维度

| 维度 | 含义 | 典型规则 |
|------|------|---------|
| **完整性** | 必填字段非空率 | `非空率 ≥ 99.9%` |
| **唯一性** | 主键不重复 | `COUNT(*) = COUNT(DISTINCT pk)` |
| **一致性** | 上下游 / 跨系统对齐 | `行数差异 < 0.1%`、`金额差异 < 0.5%` |
| **准确性** | 与业务真实值匹配 | 与业务库直查对账 |
| **时效性** | 按时产出 | 产出时间 ≤ SLA 基线 |

### 严重等级
- **P0 阻断**：DQ 失败直接停下游、告警值班、不允许发布数据
- **P1 告警**：失败但允许下游运行，需要 24 小时内修复
- **P2 监控**：仅记录与日报告知

### 边界值定义
每个度量值应明确 BLANK / 0 / 负值的业务含义：
- `BLANK / NULL`：无数据 / 不可用
- `0`：业务上确实为零
- 负值：是否合法？（如退款金额负数）

## 4. 历史数据约定

- 每个事实表必须明确数据可追溯起始时间（如 `start_date >= 2024-01-01`）
- 历史口径变更（如 KPI 公式调整）必须在指标字典中注明生效时间
- 跨口径数据的对比必须显式声明（如 "2024-03 之前 amount 单位为分"）

## 5. 行业特定规则

### 零售 / 电商
- **GMV**：成交总额（含退款 vs 不含退款两种口径需注明）
- **客单价（AOV）**：GMV / 订单数
- **复购率**：当期复购用户数 / 当期下单用户数（明确"用户首次购买"判定）
- **库存周转天数**：平均库存 / 日均销售成本
- **退货率**：退货金额 / 销售金额

### 金融
- **收益率**：必须区分简单收益率 vs 复合收益率
- **风险指标**：遵循监管口径（如 VaR、巴塞尔协议）
- **金额精度**：DECIMAL(18,6)（高精度）

### 制造
- **OEE**：可用率 × 表现率 × 良品率
- **生产周期**：考虑工作日 / 非工作日 / 班次

### 互联网 / 用户行为
- **DAU / MAU**：唯一设备 vs 唯一登录用户，需明确
- **留存率**：N 日留存的"留存"判定（活跃 / 登录 / 付费）
- **会话定义**：超时阈值（默认 30 分钟无操作）

## 6. 跨系统口径一致性

- 数仓输出指标必须与 BI 报表、业务后台展示一致
- 出现差异：先确认业务定义 → 再确认数据源差异 → 最后修代码
- 跨系统差异 > 0.5% 必须分析根因并记录到 `changes/<change>/log.md`
