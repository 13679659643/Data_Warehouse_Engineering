### 1.2 核心数据流

| 阶段 | 输入 | 处理逻辑 | 输出 |
|------|------|---------|------|
| ODS→DWD | 6类飞书原始表（含50张分表） | 合并分表、中文转英文、类型统一、空值兜底、渠道转长表 | 8张DWD明细表 |
| DWD→DWS | 4张DWD核心表 | shelf_date补全、订货数量Q关联、1~180天日期补齐、累计/计划/达成计算 | 6张DWS汇总表 |
| DWS→ADS | 6张DWS表 | JOIN商品维表、字段业务化命名、预计算昨日/今日/7天/30天快照指标 | 2张ADS核心表 |
| ADS→QuickBI | 2张ADS表 | AS别名使用字段备注、维度/度量分组、仪表板配置 | 2个数据集 + 仪表板 |

### 1.3 关键设计决策

| 决策点 | 方案 | 说明 |
|--------|------|------|
| 品牌范围 | 仅韦德品牌 | 361品牌在DWD层处理但不参与DWS/ADS计算 |
| 渠道范围 | 韦德4核心渠道 | `channel_code IN ('wd', 'japan', 'spanish', 'germany')` |
| 维度建模 | SKU + SKC双维度并行 | SKU=`style_no_size`，SKC=`style_no`，分别建表不汇总 |
| 销售明细 | 长表结构（渠道转行） | `dwd_feishu_sales_all_d` 每行=一个渠道一笔销售 |
| 分表处理 | UNION ALL对齐超集 | wd_sales_01~50以06表(55字段)为基准，缺失字段补NULL |
| 日期补齐 | shelf_date到全局最晚+180天 | 每个SKU/SKC逐日生成一行，支持1~180天计划展示 |
| 超周期处理 | 计划字段置NULL | lifecycle_day>180时plan_pre/plan_post/achievement_rate为NULL |
| 表模型 | PRIMARY KEY为主 | 支持Upsert，主键≤3列，enable_persistent_index=true |

## 三、分层架构详解

### 3.1 ODS层 - 原始数据层

**定位**：飞书多维表格同步的原始数据，保留原样不做加工。

**特点**：
- 字段以中文命名为主
- 数值字段多为varchar类型（如订货数量、已提数量）
- wd_sales_01~50分表结构不一致（41/47/55字段三种）
- 存在重复/可疑字段（如"总和"与"总和 副本"、"OTB"与"OTB(单位:亿)"）

**数据规模**：
- 韦德销售：50张分表 × ~5万行/表 ≈ 250万行
- 361销售：50张分表 × ~4万行/表 ≈ 200万行
- 商品库：韦德103字段 / 361 34字段

**关键表说明**：

| 表名 | 核心字段 | 注意事项 |
|------|---------|---------|
| wd_sales_06 | 55字段全量（含款号/尺码/销售指标） | 作为UNION ALL超集基准 |
| wd_sales_30/50 | 41字段精简版 | 缺失字段需补NULL |
| wd_pinpaikucun | 订货数量/已提数量/未提数量 | ⚠️ varchar类型，下游需CAST |
| wd_shop | 103字段含订货/到货/库存/补货/预警 | ⚠️ 实际售卖天数23个字段 |

### 3.2 DWD层 - 明细数据层

**定位**：ODS清洗标准化后的明细数据，英文snake_case命名，类型统一。

**核心处理逻辑**：
1. **分表合并**：wd_sales_01~50 / t_361sales_01~50 合并为单表
2. **结构对齐**：以wd_sales_06(55字段)为超集基准，UNION ALL时缺失字段补NULL
3. **渠道转长表**：宽表(18渠道×2=36字段)转长表(channel_code + qty + amt)
4. **类型统一**：varchar→decimal/bigint，金额DECIMAL(18,6)，销量BIGINT
5. **空值兜底**：字符串`COALESCE(NULLIF(TRIM(...), ''), 'None')`，数值`COALESCE(..., 0)`
6. **字段重命名**：中文→英文snake_case（如"销售日期"→`sales_date`）

**渠道编码映射**（dwd_feishu_sales_all_d）：

| channel_code | channel_name | 来源字段 |
|-------------|-------------|---------|
| wd | 韦德之道 | 韦德之道-销量 |
| japan | 韦德日本站 | 韦德日本站-销量 |
| spanish | 韦德西语站 | 韦德西语站-销量 |
| germany | 韦德德国站 | 韦德德国站-销量 |
| 361sport | 361sport | 361sport-销量 |
| ... | ... | ... |

**表关系**：
```
dwd_feishu_sales_361_d ─┐
                        ├──> dwd_feishu_sales_all_d (长表)
dwd_feishu_sales_wd_d ──┘

dwd_feishu_product_wd_d ─┐
                         ├──> dwd_feishu_product_all_d (统一商品库)
dwd_feishu_product_361_d┘

dwd_feishu_inventory_wdpinpai_d (独立)
dwd_feishu_otb_wd_d (独立)
```

### 3.3 DWS层 - 汇总数据层

**定位**：按业务口径汇总为可消费的宽表，完成1~180天销售计划计算。

**核心计算逻辑**：

| 指标 | 公式 | 口径章节 |
|------|------|---------|
| shelf_date补全 | 优先product_all_d.shelf_date，为空取MIN(30_est_arrival_date) | 3.5/5.5 |
| lifecycle_day | `DATEDIFF(sale_date, shelf_date) + 1` | 3.7/5.7 |
| 阶段ratio | 新品期(1~30)=0.8，热销期(31~120)=1.1，清货期(121~180)=1.0 | 4.2 |
| 订货数量Q | brand_order_arrival_d.order_qty按style_no_size关联 | 3.18/5.18 |
| cum_actual(N) | 截至第N-1天的累计销量（窗口函数ROWS UNBOUNDED~1 PRECEDING） | 4.4/6.4 |
| plan_pre | `Q * ratio / 180` | 4.3/6.3 |
| plan_post | `(Q - cum_actual) * ratio / (181 - N)` | 4.4/6.4 |
| achievement_rate | `actual_qty / plan_post`（plan_post=0时NULL） | 4.6/6.6 |
| 30天平均日销 | 已售<30天用cum_actual/sold_days，≥30天用last_30d_qty/30 | 3.12/5.12 |
| 可售周期 | 在仓库存 / 30天平均日销（1~180天用滚动窗口，超周期用当前快照） | 3.11/5.11 |
| 达成比例 | `cum_actual / order_qty` | 3.19/5.19 |
| 总订货数量 | is_replenish='是'时=订货+补货，否则=订货 | 3.20/5.20 |

**日期补齐策略**：
- 每个SKU/SKC从自身shelf_date到「全局最晚shelf_date + 180天」
- 使用`GENERATE_SERIES(0, DATEDIFF)`生成日期序列
- 没销量的日期补0，保证cum_actual连续性（修复稀疏断档Bug）

**异常表隔离**：
- SKU异常：style_no/size为空或'None'，或shelf_date补全后仍为空
- SKC异常：style_no为空或'None'，或存在SKU的shelf_date补全后为空

**表依赖关系**：
```
dws_sku_abnormal_d ─────────────┐ (异常表先跑)
dws_skc_abnormal_d ─────────────┤
                                 │
dws_sku_product_info_d ─────────┤ (商品维表)
dws_skc_product_info_d ─────────┤
                                 │
dws_sku_sales_plan_180d_d ──────┤ (核心表，复用商品维表逻辑)
dws_skc_sales_plan_180d_d ──────┘
```

### 3.4 ADS层 - 应用数据层

**定位**：面向QuickBI直接消费的宽表，字段业务化命名，预计算展示指标。

**核心处理逻辑**：
1. **JOIN商品维表**：销售计划表 JOIN 商品维表，补充IP/系列/品类/吊牌价等属性
2. **字段业务化命名**：如`actual_qty`→`daily_qty`，`cum_actual+actual_qty`→`cum_qty`
3. **sale_date_label格式化**：DWS中为"1"/"2"/.../"180"/"超周期"，ADS中为"第1天"/"第2天"/.../"第180天"/"超周期"
4. **预计算当前快照指标**：昨日/今日/7天/30天达成，通过子查询+LEFT JOIN广播到每一行
5. **cum_qty/cum_amt调整**：DWS的cum_actual为截至N-1天，ADS的cum_qty为截至当天N（含当天）

**当前快照指标计算**（口径3.21~3.25节）：

| 指标 | 计算逻辑 | ADS字段 |
|------|---------|---------|
| 昨日实际销售 | `SUM(qty) WHERE sale_date = DATE_SUB(CURRENT_DATE(), 1)` | yesterday_actual_qty |
| 昨日销售达成 | 昨日实际 / 昨日计划(后) | yesterday_achievement |
| 7天销售达成 | 近7天实际 / 近7天计划(后) | 7d_achievement |
| 30天销售达成 | 近30天实际 / 近30天计划(后) | 30d_achievement |
| 今日计划销售 | 今天的plan_post，超周期为0 | today_plan_qty |

**⚠️ 缺失字段提醒**：
当前ADS表缺少 **"系列日销"** 字段（同系列所有SKU/SKC当日销量汇总），需在ADS层新增`series_daily_qty`字段，ETL使用窗口函数：
```sql
SUM(COALESCE(sp.actual_qty, 0)) OVER (
    PARTITION BY sp.series, sp.sale_date
) AS series_daily_qty
```

## 五、关键业务规则速查

### 5.1 品牌与渠道过滤

| 场景 | 条件 | 应用层级 |
|------|------|---------|
| 品牌 | `brand = '韦德'` | DWD→DWS（DWS层仅处理韦德） |
| 渠道 | `channel_code IN ('wd', 'japan', 'spanish', 'germany')` | DWD→DWS（4核心渠道） |

### 5.2 维度键定义

| 维度 | 键 | 构造方式 | 应用表 |
|------|-----|---------|--------|
| SKU | `style_no_size` | `CONCAT_WS('-', style_no, size)` | DWS/ADS的SKU表 |
| SKC | `style_no` | 直接取`style_no` | DWS/ADS的SKC表 |

### 5.3 生命周期与阶段

| 阶段 | lifecycle_day | ratio | sales_phase |
|------|--------------|-------|-------------|
| 新品期 | 1~30 | 0.8 | 新品期 |
| 热销期 | 31~120 | 1.1 | 热销期 |
| 清货期 | 121~180 | 1.0 | 清货期 |
| 超周期 | >180 | NULL | 超周期 |

**lifecycle_day计算**：
- SKU：`DATEDIFF(sale_date, shelf_date) + 1`
- SKC：`DATEDIFF(sale_date, MIN(shelf_date)) + 1`

### 5.4 销售计划公式

| 指标 | 公式 | 适用范围 |
|------|------|---------|
| plan_pre | `Q * ratio / 180` | 1~180天 |
| plan_post | `(Q - cum_actual) * ratio / (181 - N)` | 1~180天 |
| achievement_rate | `daily_qty / plan_post` | 1~180天（plan_post≠0） |

> **Q** = 订货数量，**N** = lifecycle_day，**cum_actual(N)** = 截至第N-1天累计销量

### 5.5 库存口径

| 字段 | SKU | SKC |
|------|-----|-----|
| 在仓库存 | `COALESCE(inventory_sku, 0)` | `SUM(inventory_sku) GROUP BY style_no` |
| 可提库存 | 最新inventory_date按sku聚合`SUM(inventory_qty)` | 最新inventory_date按style_no聚合`SUM(inventory_qty)` |
| 可售周期 | 在仓库存 / 30天平均日销 | 同SKU |

### 5.6 30天平均日销计算

| 已售天数 | 计算方式 |
|---------|---------|
| =0 | NULL |
| <30 | `cum_actual / sold_days` |
| ≥30 | `last_30d_qty / 30` |

### 5.7 超周期处理规则

- lifecycle_day > 180 的行：`plan_pre`/`plan_post`/`achievement_rate` = NULL
- 超周期行只展示：日销量、日金额、累计销量、累计金额、在仓库存、可提库存、可售周期
- 展示1~180天计划时，筛选 `is_over_cycle = 0`
