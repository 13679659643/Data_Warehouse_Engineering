# 三期口径字段

## SKU/SKC字段口径定义

### 1 评级

| 项       | 说明                                                     |
| -------- | -------------------------------------------------------- |
| 数据来源 | `feishu_dwd.dwd_feishu_product_wd_d.rating` ，区分SKU维度和SKC维度   |
| 口径     | feishu_dwd.dwd_feishu_product_wd_d.rating--> feishu_dwd.dwd_feishu_product_all_d.rating-->feishu_dws.dws_sku_product_info_d.rating-->feishu_dws.dws_skc_product_info_d.rating-->feishu_ads.ads_sku_sales_plan_180d_d.rating-->feishu_ads.ads_skc_sales_plan_180d_d.rating-->QuickBI可视化层,新增查询ADS表 `rating` 字段，AS别名为中文"评级",SKU/SKC维度都需要 |
> **说明**:
>  1、从dwd到dws层，rating字段直接从wd_d表传递到all_d表，不做任何转换。
>  2、从dws到ads层，rating字段直接从product_info_d表传递到sales_plan_180d_d表，不做任何转换。
>  3、在QuickBI可视化层，SKU维度和SKC维度都需要查询ads_sku_sales_plan_180d_d表和ads_skc_sales_plan_180d_d表的rating字段，AS别名为中文"评级"。

### 2 销售计划标签-sales_plan_tag

| 项       | 说明                                                     |
| -------- | -------------------------------------------------------- |
| 数据来源 | `feishu_dws.dws_sku_product_info_d.lifecycle_day` 、`feishu_dws.dws_skc_product_info_d.lifecycle_day`，区分SKU维度和SKC维度   |
| 口径     | 如果lifecycle_day小于等于0，说明当前时间在销售计划之前，分组为"<上架时间"，如果lifecycle_day小于等于180天且大于0，说明当前时间在销售计划之中，分组为">=上架时间，<=180天"，如果lifecycle_day大于180天，说明当前时间在销售计划之后，分组为">180天"。新增一个字段sales_plan_tag，根据lifecycle_day的值，赋值为"<上架时间"、">=上架时间，<=180天"、">180天"；在feishu_dws.dws_sku_product_info_d和feishu_dws.dws_skc_sales_plan_180d_d表中，以及后续的ads层、QuickBI可视化层查询都要体现。 |

### 3 计划销量辅助字段-plan_post_assist

| 项       | 说明                                                     |
| -------- | -------------------------------------------------------- |
| 数据来源 | 插入feishu_dws.dws_sku_product_info_d和feishu_dws.dws_skc_sales_plan_180d_d 的时候，区分SKU维度和SKC维度   |
| 口径     | 1、这里要根据销售计划标签来判断， 如果销售计划标签为"<上架时间"，则计划销量辅助字段始终为计划销量值，包括超周期部分始终和计划销量一样； 
2、如果销售计划标签为">=上架时间，<=180天"，则计划销量辅助字段，需要判断一下，如果当天有实际销量，就为实际销量，没有实际销量就为计划销量；超周期部分始终和计划销量一样； 
3、如果销售计划标签为">180天"，则计划销量辅助字段和现在的plan_post(N) = (Q - cum_actual(N)) * ratio / (181 - N)逻辑一致，超周期部分始终和计划销量一样；，即始终为计划销量值。
字段需要新增到feishu_dws.dws_sku_product_info_d和feishu_dws.dws_skc_sales_plan_180d_d表中，以及后续的ads层、QuickBI可视化层查询都要体现。 |

### 4 plan_pre和plan_post逻辑调整-SKU/SKC维度

| 项       | 说明                                                     |
| -------- | -------------------------------------------------------- |
| 数据来源 | 插入feishu_dws.dws_sku_product_info_d和feishu_dws.dws_skc_sales_plan_180d_d 的时候，区分SKU维度和SKC维度   |
| 口径     | 需要结合 计划销量辅助字段plan_post_assist来设计SQL代码，我先说下逻辑：
1、这里要根据销售计划标签来判断， 如果销售计划标签为"<上架时间"，说明还没开始卖，此时实际销量肯定为0，则plan_pre = (Q - cum_plan_pre(N)) * ratio （超周期为0）； plan_post(N) = (Q - cum_plan_pre(N)) * ratio / (181 - N)，超周期为0;
2、如果销售计划标签为">=上架时间，<=180天"，则plan_pre = (Q - cum_actual(N)-cum_plan_pre(N)) * ratio （超周期为0）； plan_post(N) = (Q - cum_actual(N)-cum_plan_pre(N)) * ratio / (181 - N)，超周期始终为0； 这里需要注意的是，参考计划销量辅助字段-plan_post_assist，需要判断一下，如果当天有实际销量，就为实际销量，没有实际销量就为计划销量；
3、如果销售计划标签为">180天"，此时当前时间已经超过180天，说明已经超过销售计划了，则plan_pre = (Q - cum_actual(N)) * ratio （超周期为0）； plan_post(N) = (Q - cum_actual(N)) * ratio / (181 - N)，超周期始终为0； |

### 5 累计计算销量-SKU/SKC维度-current_cum_plan_qty

| 项       | 说明                                                     |
| -------- | -------------------------------------------------------- |
| 数据来源 | lcp.cum_plan_qty、lcps.cum_plan_qty，区分SKU维度和SKC维度 ，当前时间常量,每天刷新  |
| 口径     | 在feishu_ads.ads_sku_sales_plan_180d_d和feishu_ads.ads_skc_sales_plan_180d_d表中，新增一个字段current_cum_plan_qty，在插入数据的时候，我已经有计算好值sku的为lcp.cum_plan_qty，skc的为lcps.cum_plan_qty，取销售计划表中每个SKU或者SKC的最新累计计划销量，直接使用即可。 |
