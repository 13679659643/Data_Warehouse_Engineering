# DWD → DWS 字段口径定义

> 基于 DWD 层四张合并表（4.3/4.6/4.7/4.8）及业务逻辑说明文档（6.29版）
> 编写日期：2026-06-30
> 适用范围：韦德品牌（361品牌无首次销售日期，不适用生命周期分析）
> 目的：先确认每个字段的业务口径是否正确，再实施 DWS 层架构

---

## 一、字段口径总表

> 以下每个字段严格标注：数据来源（DWD哪张表哪个字段）、计算方式、边界条件。
> 所有字段均基于 DWD 层已清洗好的数据，不涉及 ODS 层。

---

### 1. SKC

| 项 | 说明 |
|----|------|
| 数据来源 | `dwd_feishu_product_all_d`（4.6）→ `sku` 字段 |
| 口径 | 直接取值。SKU编码，业务上等同于SKC（款号+配色） |
| 粒度 | 一个SKU一条记录 |
| 边界 | 过滤 `sku IS NOT NULL AND sku <> 'None'` |

---

### 2. 系列

| 项 | 说明 |
|----|------|
| 数据来源 | `dwd_feishu_product_all_d`（4.6）→ `series` 字段 |
| 口径 | 直接取值。SKU所属的系列名称（如"7代"、"8代"） |
| 边界 | 空值兜底为 `'None'` |

---

### 3. 上架时间

| 项 | 说明 |
|----|------|
| 数据来源 | `dwd_feishu_product_all_d`（4.6）→ `first_sales_date` 字段 |
| 口径 | 直接取值。该SKU首次产生销售的日期（DATE类型） |
| 说明 | 上架当天为销售第1天 |
| 边界 | 过滤 `first_sales_date > DATE('1970-01-01')`（排除361等无首次销售日期的品牌） |

---

### 4. 已上架天数

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | `DATEDIFF(GETDATE(), first_sales_date) + 1` |
| 说明 | 上架当天计为第1天。GETDATE() 为当前日期 |
| 示例 | first_sales_date='2026-06-01'，今天='2026-06-30'，已上架天数=30 |
| 边界 | 若 `first_sales_date IS NULL` 或 `= '1970-01-01'`，该字段为空 |

---

### 5. 销售周期标签

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段（基于已上架天数） |
| 口径 | 将180天销售周期划分为三个阶段 |

| 标签 | 条件 |
|------|------|
| 新品期 | 已上架天数 BETWEEN 1 AND 30 |
| 热销期 | 已上架天数 BETWEEN 31 AND 120 |
| 清货期 | 已上架天数 BETWEEN 121 AND 180 |

| 说明 | 180天为完整销售周期，三个阶段分配比例不同（见第24节） |
|------|------|
| 边界 | 已上架天数 > 180 时，该字段为空或标记为"超周期" |

---

### 6. 在仓库存

| 项 | 说明 |
|----|------|
| 数据来源 | `dwd_feishu_product_all_d`（4.6）→ `inventory_sku` 字段 |
| 口径 | 直接取值。该SKU当前的在仓库存数量（件/双） |
| 说明 | 来自商品库的实时快照，日刷新 |
| 边界 | 空值兜底为 0 |

---

### 7. 可提库存

| 项 | 说明 |
|----|------|
| 数据来源 | `dwd_feishu_inventory_brand_d`（4.7）→ 品牌方库存表的 `available_inventory` 字段 |
| 口径 | 直接取值。该SKU对应的品牌方可提货库存数量 |
| 说明 | 来自品牌方库存表的当日快照 |
| 边界 | 空值兜底为 0 |

---

### 8. 可售周期(天)

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | `在仓库存 / 日销量` |
| 说明 | 当前库存在当前销售速度下可维持销售的天数 |
| 分母定义 | 见下方第9项"日销量" |
| 边界 | 已售天数 = 0 时（即上架当天无历史销售），可售周期为空（分母无意义） |
| 边界 | 日销量 = 0 时，可售周期为空（防止除零） |

---

### 9. 日销量

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | **30天平均日销**。已售天数不足30天时按实际已售天数计算 |

```
已上架天数 = N
已售天数 = N - 1（今日销量次日才更新，故排除今天）

如果已售天数 = 0:  日销量 = 空（无销售历史）
如果已售天数 < 30: 日销量 = 截至昨日的累计实际销量 / 已售天数
如果已售天数 >= 30: 日销量 = 最近30天的实际销量总和 / 30
```

| 项 | 说明 |
|----|------|
| 分子（累计销量） | 见下方第11项 |
| 渠道范围 | 业务文档指定为4个渠道的销量总和：韦德之道(wd) + 韦德日本站(japan) + 韦德西语站(spanish) + 韦德德国站(germany) |
| 数据源 | `dwd_feishu_sales_all_d`（4.3）→ 按 `channel_code IN ('wd','japan','spanish','germany')` 过滤后 SUM(qty) |
| 边界 | 已售天数=0时为空 |

---

### 10. 系列日销

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | 同系列下所有SKU的"日销量"之和 |

```
系列日销(SKU_A) = SUM(同系列所有SKU的日销量)
```

| 项 | 说明 |
|----|------|
| 分组依据 | `dwd_feishu_product_all_d`（4.6）→ `series` 字段，按系列分组 |
| 计算方式 | 先用第9项逻辑算出每个SKU的日销量，再按系列 SUM |
| 说明 | 用于评估整个系列的销售热度，而非单SKU |
| 边界 | 系列内某些SKU无销售数据时，其日销量视为0参与汇总 |

---

### 11. 累计销量

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | 从上架时间（first_sales_date）到昨日，该SKU在所有渠道的实际销量总和 |

```
累计销量 = SUM(qty)
数据源: dwd_feishu_sales_all_d (4.3)
条件: sku匹配 AND sales_date BETWEEN first_sales_date AND DATE_SUB(GETDATE(), 1)
```

| 项 | 说明 |
|----|------|
| 渠道范围 | 全部渠道（与日销量不同，累计销量取所有渠道） |
| 时间范围 | 上架第一天 ~ 昨天（共已售天数天） |
| 边界 | 上架当天（已售天数=0），累计销量=0 |

---

### 12. 金额

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | 从上架时间到昨日，该SKU在所有渠道的实际销售金额总和 |

```
金额 = SUM(amt)
数据源: dwd_feishu_sales_all_d (4.3)
条件: sku匹配 AND sales_date BETWEEN first_sales_date AND DATE_SUB(GETDATE(), 1)
```

| 项 | 说明 |
|----|------|
| 渠道范围 | 全部渠道 |
| 时间范围 | 同累计销量 |
| 单位 | 元（DECIMAL(18,6)） |

---

### 13. 达成比例

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | `累计销量 / 订货数量` |

```
达成比例 = 第11项(累计销量) / 第17项(订货数量)
```

| 项 | 说明 |
|----|------|
| 分子 | 累计销量（见第11项） |
| 分母 | 订货数量（见第17项，取 order_qty_skc） |
| 含义 | 已完成订货量的百分比 |
| 边界 | 订货数量=0时为空（防止除零） |
| 补充判断 | 业务文档提到需判断SKC是否存在二级市场补货：①二级市场是否补货（是/否）②补货数量。若存在补货，分母应加上补货数量 |

### 14. 昨日销售达成情况

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | `昨日实际销售 / 昨日的销售计划(销售后)` |

```
昨日销售达成情况 = 第18项(昨日实际销售) / 昨日对应的销售计划(销售后)
```

| 项 | 说明 |
|----|------|
| 分子 | 昨日实际销售（见第18项） |
| 分母 | 昨天对应的"销售计划(销售后)"值（见第20项中1~180天的第②项） |
| 说明 | 昨天是上市第几天，就取第几天的销售计划(销售后)作为分母 |
| 示例 | 昨天是上市第5天，则分母=第5天的销售计划(销售后) |
| 边界 | 销售计划(销售后)=0时为空 |

---

### 15. 7天销售达成情况

| 项 | 说明 |
|----|------|
| 数据来源 | 计算字段 |
| 口径 | `近7天实际销量总和 / 近7天销售计划(销售后)总和` |

```
7天销售达成情况 = 近7天实际销量 / 近7天销售计划(销售后)之和
```

| 项 | 说明 |
|----|------|
| 分子 | 最近7天（含昨日）的实际销量总和 |
| 分母 | 最近7天每天对应的"销售计划(销售后)"值之和 |
| 说明 | 逐天计算销售计划(销售后)，再求和。不是用7天总销量除以一个固定值 |
| 示例 | 昨天是上市第10天，则分母=第4天+第5天+...+第10天的销售计划(销售后)之和 |
| 边界 | 分母=0时为空 |

## 二、1~180天逐日口径定义

> 每个SKU的上市第1天到第180天，每天计算4个子项：
> ① 销售计划(销售前)  ② 销售计划(销售后)  ③ 实际销售  ④ 达成情况

### 基础变量定义

| 变量 | 定义 | 说明 |
|------|------|------|
| N | 上市第N天 = `DATEDIFF(sales_date, first_sales_date) + 1` | N 取值 1~180 |
| Q | 订货数量 = `order_qty_skc` | 第17项 |
| sold_days | 已售天数 = `N - 1` | 今天不更新销量，故计算时排除第N天自身 |
| cum_actual(N) | 截至第N-1天的实际销量总和 | = SUM(qty) WHERE lifecycle_day BETWEEN 1 AND N-1 |
| phase(N) | 第N天所在阶段 | 见下方阶段表 |
| ratio(N) | 第N天所在阶段的比例 | 见下方阶段表 |

### 阶段与比例

| 阶段 | 天数范围 | ratio | 含义 |
|------|----------|-------|------|
| 新品期 | 1~30 | 80% | 新品期总目标 = Q * 80% |
| 热销期 | 31~120 | 110% | 热销期总目标 = Q * 110% |
| 清货期 | 121~180 | 100% | 清货期总目标 = Q * 100% |

---

### 第①项：销售计划(销售前)

| 项 | 说明 |
|----|------|
| 口径 | `Q * ratio(N) / 180` |
| 说明 | 固定计划，不依赖实际销售。将阶段目标量等比分配到该阶段的每一天 |
| 数据来源 | Q来自 `dwd_feishu_product_all_d.order_qty_skc`，ratio来自阶段定义 |
| 特点 | 上架前即可算出180天的计划值，不随实际销售变化 |

**示例**（Q=1000）：

| 天 | 阶段 | ratio | 计划(前) |
|----|------|-------|----------|
| 1 | 新品期 | 80% | 1000*0.8/180 = 4.444 |
| 2 | 新品期 | 80% | 1000*0.8/180 = 4.444 |
| 30 | 新品期 | 80% | 1000*0.8/180 = 4.444 |
| 31 | 热销期 | 110% | 1000*1.1/180 = 6.111 |
| 120 | 热销期 | 110% | 1000*1.1/180 = 6.111 |
| 121 | 清货期 | 100% | 1000*1.0/180 = 5.556 |
| 180 | 清货期 | 100% | 1000*1.0/180 = 5.556 |

---

### 第②项：销售计划(销售后)

| 项 | 说明 |
|----|------|
| 口径 | `(Q - cum_actual(N)) * ratio(N) / (180 - sold_days)` |
| 展开 | `(订货数量 - 截至昨天的累计实际销量) * 当前阶段比例 / (180 - 昨天是第几天)` |
| 说明 | 有了实际销售后，用剩余可销量按当前阶段比例动态分配给剩余天数 |
| 数据来源 | Q来自 `dwd_feishu_product_all_d.order_qty_skc`；cum_actual来自 `dwd_feishu_sales_all_d` 按lifecycle_day累计 |
| 特点 | 每天更新。实际卖得越多，后续计划越低；反之亦然 |

**示例**（Q=1000）：

| 天N | cum_actual(N) | 阶段 | 计算过程 | 计划(后) |
|-----|---------------|------|----------|----------|
| 1 | 0（无历史） | 新品期 | (1000-0)*0.8/(180-0) | 4.444 |
| 2 | 第1天实际=5 | 新品期 | (1000-5)*0.8/(180-1) | 4.469 |
| 5 | 前4天总和=50 | 新品期 | (1000-50)*0.8/(180-4) | 4.318 |
| 31 | 前30天总和=200 | 热销期 | (1000-200)*1.1/(180-30) | 5.867 |
| 32 | 前31天总和=200+plan(31) | 热销期 | (1000-205.867)*1.1/(180-31) | 5.880 |

> 注：cum_actual(N)中的N-1天的实际销量，**只包含实际卖出的量，不包含计划量**。计划消耗已隐含在分母的"剩余天数"中。

---

### 第③项：实际销售

| 项 | 说明 |
|----|------|
| 口径 | 该SKU在上市第N天的实际销量 |

```
实际销售(N) = SUM(qty)
数据源: dwd_feishu_sales_all_d (4.3)
条件: sku匹配 AND DATEDIFF(sales_date, first_sales_date) + 1 = N
渠道范围: 全部渠道（与"日销量"仅取4个渠道不同）
```

| 项 | 说明 |
|----|------|
| 数据来源 | `dwd_feishu_sales_all_d`（4.3）→ `qty` 字段，按 sku + lifecycle_day 聚合 |
| 渠道范围 | 全部渠道（361的4个 + 韦德的18个，韦德品牌实际使用18个渠道总和） |
| 边界 | 该天无销售记录时为 0 |
| 说明 | 匹配方式：`SUMIFS(销量, 销售表SKC列, 当前SKC, 销售表已上架天数列, N)` |

---

### 第④项：达成情况

| 项 | 说明 |
|----|------|
| 口径 | `第③项(实际销售) / 第②项(销售计划-销售后)` |

```
达成情况(N) = 实际销售(N) / 销售计划_后(N)
```

| 项 | 说明 |
|----|------|
| 分子 | 第N天的实际销量 |
| 分母 | 第N天的销售计划(销售后) |
| 含义 | >100% 表示超预期完成，<100% 表示未达标 |
| 边界 | 销售计划(销售后)=0时为空 |

**示例**（Q=1000）：

| 天 | 实际销售 | 计划(后) | 达成情况 |
|----|----------|----------|----------|
| 1 | 5 | 4.444 | 5/4.444 = 112.5% |
| 2 | 10 | 4.469 | 10/4.469 = 223.8% |

## 三、1~180天完整口径速查表

对每个 SKU 的上市第 N 天（N = 1, 2, 3, ..., 180）：

| 子项 | 口径 | 数据源 | 依赖 |
|------|------|--------|------|
| ① 销售计划(销售前) | `Q * ratio / 180` | 4.6(order_qty_skc) + 阶段定义 | 仅依赖订货量，固定值 |
| ② 销售计划(销售后) | `(Q - cum_actual) * ratio / (180 - N + 1)` | 4.6(order_qty_skc) + 4.3(累计qty) + 阶段定义 | 依赖截至N-1天的实际销量 |
| ③ 实际销售 | `SUM(qty) WHERE lifecycle_day = N` | 4.3(qty) | 当天全渠道实际销量 |
| ④ 达成情况 | `③ / ②` | 计算 | 实际 vs 动态计划 |

其中：
- `Q` = `dwd_feishu_product_all_d.order_qty_skc`
- `ratio` = 新品期0.8 / 热销期1.1 / 清货期1.0
- `cum_actual` = 截至第N-1天的实际销量总和（来自4.3，全渠道SUM(qty)）
- `N` = `DATEDIFF(sales_date, first_sales_date) + 1`

### 问题2：销售计划(销售后)的cum_actual口径

业务文档原文：
```
第2天：(订货数量 - 第1天实际销量) * 80% / (180-1)
第3天：(订货数量 - 第1天实际 - 第2天计划) * 80% / (180-2)
```

第3天的分子中扣减了"第2天计划"而非"第2天实际"。这意味着 cum_actual 不是纯实际销量的累计，而是 **实际 + 已分配计划** 的混合扣减。

| 理解A（严格按递推） | 理解B（简化版） |
|---------------------|-----------------|
| 第N天分子 = Q - 截至N-1天的(实际+已分配计划)总和 | 第N天分子 = Q - 截至N-1天的实际销量总和 |
| 需逐天递推计算 | 可直接用窗口函数算 |
| 与业务文档递推逻辑一致 | 与业务文档有微小差异（前几天<0.5%） |

**需确认**：采用哪种理解？
